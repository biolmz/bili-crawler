### 本次更新

#### macOS 内置静态 FFmpeg（核心修复）

之前的 macOS 版启动后始终提示「未检测到 FFmpeg」。原因有两条：

1. 从 Finder 启动的 `.app` **不继承终端 PATH**，`/opt/homebrew/bin` 这类路径根本不在搜索范围内——而 `ffmpeg` 恰恰装在那里
2. 原先的兜底下载源 evermeet.cx 只提供 x86_64 构建，Apple Silicon 要靠 Rosetta 才能跑

现在改为**把静态 ffmpeg 直接打进安装包**：构建时按目标架构取 `ffmpeg-static` b6.1.1，放进
`BiliCrawler.app/Contents/Frameworks/ffmpeg/bin/ffmpeg`，运行时优先命中该路径，与 PATH 无关。
代价是 dmg 体积从约 26 MB 涨到 44 / 53 MB。

> FFmpeg 以 GPL/LGPL 授权随包分发，许可证详见项目 `LICENSE.txt`。

#### 新增 Linux 版本

- deb 包：装到 `/opt/bilicrawler`，软链 `/usr/bin/bilicrawler`，带 `.desktop` 与 512px 图标，`postinst` 会刷新桌面缓存
- tar.gz 包：解压后 `./bilicrawler` 直接运行
- 基于 Ubuntu 22.04 构建，**要求 glibc ≥ 2.35**（Ubuntu 22.04+ / Debian 12+ / Fedora 36+）
- Linux 包**未内置 FFmpeg**：`sudo apt install ffmpeg`，或在程序里按提示自动下载

#### 新增 `--self-test` 启动自检

```
BiliCrawler --self-test
self-test ok  v1.1.1  python 3.12.x  Tk 8.6
ffmpeg: /path/to/ffmpeg
data_dir: ...
```

真建一个 Tk 窗口再销毁，能验证 GUI 运行时可用；CI 里 Linux 用 `xvfb-run` 跑同一套自检。

#### 其它

- 平台差异集中到 `bili_core.py`：数据目录、默认下载目录、FFmpeg 查找、字体、打开文件管理器各自分支
- 字体按系统回退：PingFang SC / Noto Sans CJK SC / Microsoft YaHei UI
- 新增下载页 `docs/index.html`（单文件、无外部依赖、自动识别平台与架构）

### 安装提示

**macOS**：打开 dmg 拖进 Applications，首次启动右键 → 打开。若提示「已损坏」，终端执行

```
xattr -dr com.apple.quarantine /Applications/BiliCrawler.app
```

安装包为 **ad-hoc 签名**，未做 Apple 公证，上述提示属正常现象。

**Linux**：

```
sudo apt install ./bilicrawler_amd64.deb
```
